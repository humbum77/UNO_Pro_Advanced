## 1. Автоматизация: канонический декодер был заперт за проверкой профиля

`storage.py` запускал декодер только если `read_automation()['profile']`
оказывался непустым. У обычных заводских пресетов профиль `None`.

Измерено по корпусу:

| | |
|---|---|
| пресетов с native-событиями автоматизации | **206** |
| с распознанным профилем | **4** |
| дорог до редактора | **4** |

До правки редактор получал 0 значений автоматизации у 191 пресета, молча.

### Исправление

Декодер вызывается всегда. Профиль влияет только на разрешение имён
параметров. Добавлены поля, позволяющие интерфейсу отличать «не знаем» от
«знаем 0»:

- `container_entry_count` — сколько событий в контейнере
- `lanes_populated` — сколько дорожек реально заполнено
- `status` — формулировка причины

### Чего это НЕ даёт

`decode()` возвращает для этих пресетов `count`, но **пустой** `parameters`:
цели не разрешены. Панель автоматизации останется пустой — не из-за ворот, а
потому что не решена задача Parameter Selection. Это и есть оставшийся
блокер из отчёта от 2026-09-23.

Статус 229 пресетов `unknown parameter selection`, 11 `targets unresolved`.

## 2. Матрица: читалась, но никогда не записывалась

`matrix_codec.encode_matrix` и `ui_route_to_file_change` **не вызывались нигде**.
В модели `Preset` полей матрицы не было:

```
Preset fields: name, number, params, sequence, tags, category, source
```

Данные жили только в `self.values['MAMT0'…'MFADE15']`. При сохранении:

- если у пресета есть `native_raw_hex` → пишутся **исходные байты дословно**
- иначе → JSON без матрицы

Правка терялась молча.

### Исправление

- `Preset.matrix` — 16 маршрутов рядом с моделью
- `App._collect_matrix()` — читает GUI (имена) и переводит в FILE id через реестр
- `native_automation.apply_matrix_to_file()` — пишет в native-байты
- `matrix_codec.write_matrix_to_file()` — уровень файла, хвост после 297
  байт сохраняется
- `storage.save_working_preset()` передаёт матрицу в writer

### Проверено end-to-end

```
route 1 amount 54 -> правка на 33 -> сохранение -> повторное чтение: 33
хвост файла идентичен
остальные маршруты не тронуты
длина секвенции, gate, accent: без изменений
размер файла 1081 -> 1081 байт
```

## 3. Пересечение матрицы и полей секвенсера

Область матрицы — биты 1501…2015 (байты 188…251). Поля секвенсера лежат внутри:

| Поле | Биты | Попадает в |
|------|------|-----------|
| длина секвенции (207–208) | 1656…1664 | route 5, route 6 |
| общий Gate (209–210) | 1672…1686 | route 6 |
| общий Accent (212) | 1696…1702 | route 7 |

**Маршруты 5, 6 и 7 — это не независимые маршруты.** Их «значения» в
интерфейсе являются байтами секвенсора. Интерфейс показывал их как маршруты
матрицы.

### Исправление

- `matrix_codec.SEQUENCER_OVERLAP_SLOTS = (5, 6, 7)` (нумерация с 1)
- `encode_matrix(..., allow_overlapping=False)` отказывает
- writer сравнивает с исходным состоянием файла и пишет **только изменённые**
  маршруты, поэтому нетронутые 5–7 сохраняют байты как есть
- попытка изменить маршрут 5, 6 или 7 отклоняется с внятным сообщением

Защита двухуровневая: барьер в `native_automation` и барьер в самом кодеке.
Отключение одного оставляет другой — проверено.

## 4. Подписи назначений и диапазон amount

**Подписи.** `app.py` брал `MATRIX_DESTINATIONS[file_id]`, то есть native FILE id
использовался как индекс UI-списка. Список короче нативного перечисления:
FILE `0x32…0x35` (Mod 13…16) в него не входят и рисовались как `FILE 0x32` без
имени. Теперь идёт обращение к реестру: `decode_destination_file_id()`,
`decode_source_file_id()`. Проверено: FILE `0x32` = `Mod 13 Amount`.

**Диапазон.** Интерфейс давал `-64..64`, формат — `-63..+64`. Значение −64
декодер отверг бы. Теперь диапазон берётся из кодека
(`MATRIX_AMOUNT_RANGE`) в трёх местах: ползунок, чтение и отображение.

## 5. Измерение: где проходит граница вычислимого декодера

Задача из отчёта от 2026-09-23: LUT — oracle, а не декодер. Измерено, какая
часть состояния вычислима из offset/mask, а какая требует явного правила.

Классификация всех 83 наблюдённых полей (7638 записей):

| Класс | Полей | Что нужно |
|-------|-------|-----------|
| `identity` | 18 | только offset/mask |
| `constant offset` | 1 (CC 98, −1) | смещение |
| `monotonic permutation` | 15 | явная таблица соответствия |
| `non-monotonic` | 49 | настоящая формула разрядной раскладки |

Итого **19 из 83** воспроизводятся одной вычислимой моделью, **15** — с
таблицей, и **49** требуют индивидуальной формулы на каждое поле.

49 нелинейных полей — это ровно те, у которых значение разложено по нескольким
байтам с переплетением бит. Пример: формула CUTOFF 1..512
(`Docs/history/CUTOFF_PACKING_1_512.md`) — 9 бит значения, разложенные на три
байта нелинейно.

### Оценка объёма

- **Сделать:** 19 полей — это модель вида offset/mask/decode/encode плюс
  проверка против oracle
- **Средний объём:** 15 полей — перечислить соответствие
- **Основная работа:** 49 полей — по формуле на поле, каждая требует
  подтверждения на захватах

Плюс ограничение таблицы: 7638 записей на 11136 заявленных замеров
(87 controls × 128 points). **38 из 83 полей** никогда не наблюдались во всех
128 положениях — их нельзя проверить oracle'ом, для них нужны новые съёмки.

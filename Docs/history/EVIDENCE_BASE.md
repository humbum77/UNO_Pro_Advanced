# База доказательств и тесты по ней

## Что лежит в `tests/fixtures/`

`UNO_UNIFIED_NORMALIZED_FINAL_2026-09-29.sqlite` (47 МБ) — сводная база
наблюдений. Открывается **только на чтение**: прогон тестов не может изменить
доказательства. Файл не отслеживается git — он версионируется как бинарный
fixture осознанно, а не едет в каждом коммите.

28 таблиц. Ключевые для этого проекта:

| Таблица | Строк | Назначение |
|---------|-------|-----------|
| `matrix_hax_files` | 36 | контрольные матрицы, по 2 представления на пару |
| `matrix_controlled_presets` | 2 | исправленные пользователем `.unosyp` целиком |
| `matrix_evidence_registry` | 18 | статус каждой пары, включая `VALIDATED_REPLACEMENT` |
| `evidence_exclusions` | 6 | почему конкретные данные исключены |
| `preset_issue_ledger` | 5 | классы дефектов захватов |
| `normalization_policy` | 7 | правила: namespace, дубликаты, гипотезы |
| `namespace_registry` | 4 | разведение FILE / WIRE / SEMANTIC / UI_ORDER |
| `unosyp_complete_hex` | 1 003 | полный корпус пресетов |
| `automation_page_registry` | 11 080 | страницы автоматизации |
| `parameter_evidence` | 4 295 | доказательства по параметрам |
| `xlsx_row_provenance` | 27 997 | провенанс строк таблиц |

## Политика, зафиксированная в самой базе

`normalization_policy` и `namespace_registry` требуют разведения четырёх
пространств имён: `FILE`, `WIRE`, `SEMANTIC`, `UI_ORDER`. Именно нарушение
этого требования породило баг со сдвигом `Mod N Amount` на 4 позиции.

`hypothesis_rule`: сырые данные, интерпретация и подтверждённый факт —
разные вещи, и гипотеза не должна выдаваться за факт.

## Что даёт база тестам

`tests/evidence_db.py` — тонкая обёртка над базой. `tests/test_matrix_codec.py`
декодирует реальные контрольные захваты вместо выдуманных ожиданий.

**Результат по контрольным матрицам: 16 из 18 совпали с реестром.**

Два не совпали — `FiltEnvSus` и `AmpEnvRel`, оба декодируются в 0 («источник
не задан»). Это не дефект кодека, а свойство данных, и база это фиксирует:

- `evidence_exclusions:5-6` — `Matrix.zip` содержит некорректно сохранённые
  контрольные файлы; пользователь заменил `AmpEnvSus` и `GATE 2 IN`
- `preset_issue_ledger:5` — `DATASET_HAS_MISSAVED_CONTROLS`, severity `KNOWN`
- заменённые два не имеют статуса `VALIDATED_REPLACEMENT`, значит и эти два
  не проверены

Они объявлены в `evidence_db.UNRESOLVED_MATRIX_CAPTURES` как **ожидаемое
неизвестное**: тест требует, чтобы они остались неразрешёнными. Если новый
захват начнёт декодироваться, тест это заметит и потребует решения, а не
молча примет.

**Статус: 16 подтверждённых, 2 UNKNOWN, требующих пересъёмки.**

## Почему тесты проверены на полезность

Обе характерные ошибки проверены откатом: тест обязан падать, если поведение
вернётся к прежнему.

| Откат | Что происходит |
|------|----------------|
| `ui_route_to_file_change` снова берёт индекс списка | `test_ui_names_cannot_override_the_file_id` → `AssertionError: 1 != 2 : Volume: a UI index leaked into the FILE id` |
| геометрия источника возвращается к модели «следующая ячейка» | `test_validated_captures_match_the_registry` → `AssertionError: 0 != 28` |

## Как обновлять

Новый срез доказательств — заменить файл в `tests/fixtures/`, обновить
`UNRESOLVED_MATRIX_CAPTURES`, если состав изменился, прогнать
`python -m unittest tests.test_matrix_codec`. База открывается только на
чтение, поэтому случайно испортить её прогоном нельзя.

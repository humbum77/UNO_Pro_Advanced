# Матрица модуляции — списки назначений и источников (2026-09-29)

Оператор передал 2026-09-29 списки пунктов назначения и источников с их
hex-идентификаторами. Это прямое утверждение, полученное с прибора.

## 1. Что даёт этот список

Отчёт по матрице держал `Source CLOSED 38/38`, а `Destination OPEN`. Причина
OPEN была в порядке приоритета доказательств: для назначений он требовал
аппаратного захвата раньше, чем официального числового перечисления VST3, на
которое опирался реестр.

Списки оператора снимают этот вопрос. Проверка реестра против них:

| проверка | источники | назначения |
|----------|-----------|------------|
| число пунктов | 38 = 38 | 54 = 54 |
| `file_raw_dec` равен индексу | да, все 38 | да, все 54 |
| `wire_raw_hex` равен `file_raw_hex` | да, все 38 | да, все 54 |
| семантика совпадает по порядку | да, кроме одного написания | да, все 54 |

**Оба списка совпадают с реестром полностью.** Расхождений в идентификаторах
нет ни одного.

Единственное расхождение — написание: реестр пишет `Mod Wheel`, прибор
`MODWHEEL`. Тот же параметр, разница только в пробеле. Объявлено в тесте как
`KNOWN_SPACING_VARIANTS`, а не спрятано нормализацией: тест
`test_the_only_spelling_difference_is_the_declared_one` падает, если появится
второе расхождение.

## 2. Порядок в UI — отдельная сущность, и он корректен

Смещение UI-порядка относительно file id выглядит как ошибка, но проверено и
ею не является.

**Назначения: UI-индекс равен рангу среди выбираемых.** 54 пункта, из них
49 выбираемых, и их UI-индексы — ровно 0..48 без пропусков и дублей. Пять
невыбираемых имеют пустой UI-индекс:

| file id | назначение | статус |
|---------|-------------|--------|
| `0x01` | Pitch | `CONFIRMED_HIDDEN`, `selectable_in_ui=0` |
| `0x16` | LFO 1 Retrigger | то же |
| `0x19` | LFO 2 Retrigger | то же |
| `0x22` | Gate Out 1 | то же |
| `0x24` | Gate Out 2 | то же |

Именно поэтому «провал» в конце списка — `file 53 → ui 48`: пять скрытых
пунктов не входят в UI-нумерацию. Отсутствующие значения UI — ровно
`{49, 50, 51, 52, 53}`.

**Источники: UI-порядок приведён к порядку прибора по требованию оператора.**
Изначально граф `ui_position_0based` содержал перестановку: `FILTER ENV` и
`AMP ENV` стояли на позициях 25 и 30, а блоки `FILTER ENV A/D/S/R` и
`AMP ENV A/D/S/R` — перед ними на 21..24 и 26..29. Перестановка была
внутренне согласована, но расходилась с прибором.

Переписано 17 строк из 38, остальные 21 уже были верными:

### 2.1 Расхождение двух копий списка

Выпадающий список источников в `app.py:1744` питается собственной ручной
копией `MATRIX_SOURCES`, а не реестром, и **она уже была в порядке прибора**.
Расхождались две копии: ручной список и граф UI в реестре.

Ручной список не трогался — он был верен. Исправлен реестр, который по
устройству является единственным источником истины.

Остаточная косметическая разница: прибор пишет `CV 1 IN` и `GATE 1 IN`
заглавными, ручной список в `app.py` — тоже, а реестр — `CV 1 In` и
`Gate 1 In`. Реестр приведён к написанию прибора в тесте как
`KNOWN_SPACING_VARIANTS`. Список в `app.py` можно убрать руками и получать из
реестра, но это отдельная правка: она затронет четыре подписи в выпадающем
списке, и пользователь её не просил.

### 2.2 Почему запись не затронута

Изменён только столбец `ui_position_0based`, и только у строк `source`.
Проверено сравнением с предыдущим коммитом:

| столбец | изменённых значений |
|---------|---------------------|
| `ui_position_0based` | 17 |
| `file_raw_hex`, `file_raw_dec` | 0 |
| `wire_raw_hex`, `wire_raw_dec` | 0 |
| `semantic` | 0 |
| `selectable_in_ui` | 0 |
| `evidence`, `confidence` | 0 |

`matrix_codec` по контракту никогда не использует UI-индекс как FILE
идентификатор, поэтому 15 тестов кодека на реальных контрольных захватах
проходят без изменений, и байты записи не меняются.

## 3. Блок MOD N AMOUNT

`0x26..0x35` — это `MOD 1 AMOUNT` … `MOD 16 AMOUNT`, ровно в порядке оператора.
Проектные заметки раньше говорили «FILE id `0x26..0x35` (38..53), UI-порядок
33..48»; теперь проверено, что UI-порядок действительно 33..48, потому что
пять скрытых пунктов сдвигают нумерацию.

## 4. Что внесено

- `tests/test_matrix_operator_lists.py` — 9 тестов. Списки оператора вписаны
  дословно и проверяются против реестра по file id, wire id и семантике, плюс
  блок `MOD N`, правило UI-ранга и объявленное единственное расхождение
  написания. Реестр не может разойтись с прибором незаметно.

## 5. Чего этот список не закрывает

- Он ничего не говорит о **величине** модуляции и о разряде параметра. Диапазон
  количества остаётся тем, что подтвердил кодек: `-63..+64`.
- Он не даёт порядка источников в панели GUI сверх уже имеющейся перестановки.
  Перестановка источников в реестре внутренне согласована, но прибор её явно не
  подтверждал.
- Он не касается Parameter Selection: выбор параметра по-прежнему в памяти
  прибора и в файл не попадает.

# Parameter Selection — итог (2026-09-29, версия 4)

Цель: закрыть блокер Parameter Selection, из-за которого 206 пресетов корпуса
показывают ноты при пустой панели автоматизации.

Решающий набор: `D:\Documents\IK Multimedia\UNO Synth Pro Editor\1test\statistical benchmark`
— 23 пресета, по одному на каждый автоматизируемый параметр, плюс `BASE` без
автоматизации. Это первый purpose-built набор с настоящей меткой: имя файла
задано оператором вместе со значением, а контроль выбран явно.

## 1. Состав набора

Все 23 параметра из `automation_metadata.AUTOMATABLE` сняты по одному,
значения указаны в именах: WAVE1 64, TUNE1 0, WAVE2 64, TUNE2 0, WAVE3 64,
TUNE3 0, LEVEL1 50, LEVEL2 50, LEVEL3 50, CUTOFF1 256, CUTOFF2 256, RES1 64,
ENV1 32, RES2 64, ENV2 32, SPACING 32, LFO1 32, LFO2 32, DRIVE 64, MOD 50,
DELAY 50, REVERB 50, NOISE 64.

## 2. Запись автоматизации параметр не кодирует

23 параметра дают **18 различных записей**, и совпадения точно по значению:

| запись | параметры | значение |
|--------|-----------|----------|
| `01 02 00 00 04` | DRIVE, NOISE, RES1 | 64 |
| `01 02 00 00 02` | ENV1, SPACING | 32 |
| `01 02 28 14 03` | LEVEL2, LEVEL3 | 50 |
| `01 02 00 00 00 00` | TUNE1, TUNE3 | 0 |

**Все 18 групп записи однородны по значению** — ни одна группа не смешивает
значения. То есть запись определяется значением, а не параметром.

Обратная проверка: параметры с одинаковым значением.record расходятся
(например, значение 32 у пяти параметров даёт четыре разные записи), то есть
запись не является и функцией одного значения. Она зависит от упаковки
значений по слотам и о параметре не сообщает.

Это подтверждает вывод версий 2 и 3 на специально построенном наборе, а не на
именах файлов.

## 3. Флага включения параметра нет нигде в файле

Проверен весь файл целиком, а не только состояние: искалось смещение, где у
каждого из 23 пресетов установлен ровно один бит и каждый параметр отличается
тем, какой именно. **Таких смещений ноль.**

Второй критерий, слабее: смещение, где значение уникально для каждого
параметра. **Таких смещений тоже ноль.**

Вывод: отдельного «этот параметр автоматизирован» в файле нет.

## 4. Идентичность параметра в состоянии выводится только косвенно

Параметры различаются тем, что пишут своё значение в собственные слоты
состояния. Смещения, принадлежащие ровно одному параметру:

```
0x0012  TUNE1     0x0014  LEVEL2    0x0025  CUTOFF1   0x002C  DRIVE
0x002E  LEVEL2    0x002F  LEVEL2    0x0043  ENV1      0x0044  ENV1
0x004A  DRIVE     0x004D  ENV2      0x00B2  SPACING   0x0112  MOD
```

Но слоты не разбивают пространство: 0x0026–0x0029 пишут сразу около десяти
параметров, то есть это общая область значений автоматизации шага, а не
индивидуальные слоты параметров. Собственные слоты значений параметров
известны из `state_decoder_map.json`.

## 5. Два пресета из 23 не записали состояние

`DELAY = 50` и `WAVE3 = 64` не отличаются от `BASE` ни одним байтом в
состоянии, хотя страницы автоматизации изменены (159 и 157 байт). Либо
автоматизация для них не пишется, либо это дефект съёмки. Различить по
имеющимся файлам нельзя.

## 6. Итог: Parameter Selection не является задачей декодирования

Информации о том, какие параметры автоматизированы, в файле нет. Блокер
`decode()` не закрывается улучшением разбора: `count` возвращается верно,
а имена параметров взять неоткуда.

Это меняет решение. Варианты:

- **A. Считать набор фиксированным.** Принять, что автоматизация применяется к
  известному набору параметров в известном порядке, и читать/писать значения по
  их слотам в состоянии. Требует подтверждения от устройства, какой набор
  активен.
- **B. Дать выбор пользователю.** Редактор спрашивает, какие параметры
  автоматизировать, и пишет значения в слоты этих параметров. Формат не
  зависит от несуществующего в файле поля, работает всегда.
- **C. Проверить, не хранится ли выбор вне пресета** — в глобальной памяти
  прибора или в MIDI-конфигурации. Тогда в файл он не попадает по
  определению, и вариант A становится единственно возможным.

Вариант B реализуем сразу и не ждёт новых съёмок.

## 7. Отозванные утверждения

Версия 2: маска 0x01ED, 16 бит. Снято — в файлах, для которых она была
выведена, поля выбора нет.

Версия 3: «байт выбора по модулю 256 суммируется из кодов параметров»,
веса ENV1=86, ENV2=122, SPACING=202, DRIVE=214, REVERB=154. Снято — пять
уравнений на пять неизвестных дают решение гарантированно, и оно ошибается на
всех четырёх независимых проверках.

Сигнал «REVERB не участвует, все четыре пары с REVERB дают 0x00» остаётся
необъяснённым, но на новом наборе не воспроизводится: `REVERB = 50` пишет
состояние и даёт собственную запись `01 02 40 13 03`. Значит нули в серии PSEL
относятся к тем съёмкам, а не к REVERB как таковому.

## 7. Подтверждённый порядок автоматизации

Оператор подтвердил порядок прибора 2026-09-29:

```
WAVE1; TUNE1; WAVE2; TUNE2; WAVE3; TUNE3;
LEVEL1; LEVEL2; LEVEL3; NOISE; CUTOFF1; RES1; ENV1;
CUTOFF2; RES2; ENV2; SPACING; LFO1; LFO2;
DRIVE; MOD; DELAY; REVERB;
```

Два факта, которые в проекте были неверны:

- **NOISE автоматизируется** и стоит между `LEVEL3` и `CUTOFF1`, то есть
  девятым. В `uno_step_automation_decoder.PARAMETERS` он стоял последним,
  в `automation_metadata` его не было вовсе.
- **VELOCITY к автоматизации отношения не имеет.** Он принадлежит группе
  параметров шага `GATE; ACC; TIE; VELOCITY; LENGTH` и оказался на панели
  автоматизации только потому, что в GUI ему не нашлось места.

Внесено:

- `automation_metadata.AUTOMATION_ORDER` — 23 параметра в порядке прибора.
- `automation_metadata.STEP_PARAMETERS` — группа параметров шага.
- `NOISE` зарегистрирован в `PARAMETERS` как автоматизируемый, диапазон 0..127.
- `VELOCITY` помечен статусом `CONFIRMED step parameter; NOT a held-Step Automation lane`.
- `uno_step_automation_decoder.PARAMETERS`: `NOISE` перенесён на позицию 9,
  порядок вынесен в `DECODER_PARAMETER_ORDER`.
- `tests/test_automation_order.py` — 7 тестов, фиксируют порядок, позицию
  `NOISE` и статус `VELOCITY`.

`app.py` править не потребовалось: полоса `VELOCITY` уже обрабатывалась как
значение шага (`_step_velocity`, `st.velocity`), неверной была только метка.
Отображение CC привязано к имени полосы (`app.py:3337`), а не к её позиции,
поэтому перестановка списка ни на что не повлияла; чинить пришлось только
`test_no_guessed_automation_sends`, который молча полагался на то, что первая
полоса — это `CUTOFF 1`. Тест теперь обращается к полосе по имени.

Панель GUI теперь показывает 24 позиции (23 параметра прибора плюс `VELOCITY`)
в порядке прибора. Если перестановка панели нежелательна — это отдельное
решение, вернуть порядок панели можно одной строкой.

## 8. Что делать нельзя

- Считать имя файла меткой параметра: 21 группа побайтово идентичных файлов с
  конфликтующими именами, включая `ENV1_32` = `SPAC_32` = `TEST_ENV1_PLUS32`.
- Считать 164 профиля «точными»: они сопоставлены по совпадению байтов, а
  совпадение байтов параметр не различает.
- Искать флаг включения дальше: его нет, см. раздел 3.

# STORE в панели библиотеки UNO

Рабочая база: `UNO_Pro_Advanced_v0.9.7-beta2-STORE-SEQUENTIAL-FIX.zip`.

## Поведение

На странице PRESET LIBRARY кнопка STORE находится над списком аппаратных слотов UNO. Выделение строки задаёт только слот назначения. Нажатие STORE вызывает существующую транзакцию с этим номером и показывает подтверждение перед перезаписью. Источник данных — текущий edit buffer устройства; выбор целевого слота не загружает его.

В панели нет отдельной Send: она дублировала STORE. Кнопка Receive сохраняет текущий аппаратный edit buffer локально; она не выполняет отдельную загрузку выделенного слота перед сохранением. При перетаскивании локального бинарного `.unosyp` на аппаратный слот STORE получает состояние и все четыре страницы **перетаскиваемого файла** непосредственно из его байтов. При наличии полного `sequence.native_raw_hex` это также работает для локального JSON пресета. При отсутствии полного бинарного исходника передача отклоняется до отправки MIDI. Операция отдельно подтверждает имя файла и слот.

Верхняя кнопка STORE продолжает спрашивать номер назначения. Блокировка повторной операции и существующая диагностика таймаута сохранены.

## Сохранённая аппаратная логика

Не менялись выбор банка перед STORE без Program Change, сбор страниц 0x29 и состояния 0x37, последовательность 0x11 → 0x23 → 0x28 с продолжениями → 0x33, последующие Bank Select/Program Change и 0x32. При перетаскивании устранён предварительный вызов `_select_hw_preset`, который отправлял Program Change до чтения текущего буфера.

## Проверка

`python -m unittest discover -s tests -p test_store_library.py -v`: 4 проверки проходят. Проверены выбор аппаратного слота без его загрузки, передача состояния и страниц перетаскиваемого файла, а также отказ для файла без полного бинарного исходника. Все 16 предоставленных binary capture успешно преобразованы в 0x28 base и четыре continuation-кадра без отправки MIDI.

Статус: SOFTWARE PASS для маршрута интерфейса и подготовки файла. Реальную запись перетаскиваемого файла на устройстве нужно проверить на тестовом слоте; HARDWARE PASS для прямой передачи файла не заявляется. При ошибках ACK существующая реализация может не давать отдельной диагностики кадра с `data[6] == 0x01` — см. `UNO2.2_STORE_WORK_REPORT_2026-09-22.docx`.

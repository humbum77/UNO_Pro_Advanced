# Интеграция декодера Step Automation

В базу `STORE-LIBRARY-PANEL` добавлен `uno_step_automation_decoder.py`. Вызов происходит из `native_automation.read_automation` при загрузке локального бинарного `.unosyp` с четырьмя страницами переменной длины; данные доступны в `sequence.native_automation` и через `unosyp_seq_decoder.parse_unosyp`.

Поля результата: `step`, `entry_count`, `selection_hex`, `payload_hex`, `pages_match`, `profile`, `entries` и `mapping`. Для точного профиля `entries` содержат имена, raw HEX, native значения и signed-представление ENV1/ENV2/SPACING. При отсутствии точного совпадения статус `PARTIAL`, `entries` пуст; байты сохраняются. В интерфейсе Sequencer выводится имя распознанного профиля или PARTIAL.

## Factory multi-step correction

Заводской `FAKE 808(1).unosyp` подтвердил второй вариант контейнера. Четыре
automation extension нельзя сравнивать как зеркальные копии: Page 1 содержит
локальные записи, а каждая следующая страница начинается с накопленного потока
native values предыдущих страниц и затем содержит записи своих 16 шагов.

Reader теперь отделяет накопленный префикс, разбирает page-local записи
`Step / Count / Selection / Values` и для подтверждённой заводской сигнатуры
выдаёт линию `CUTOFF1`. В тестовом пресете обнаружены точки на шагах
6, 7, 11, 23, 27, 54, 55 и 59. Они переносятся в `Sequence.automation` как
`CUTOFF 1` и отображаются редактором. Остальные цели этой записи не именуются,
пока их selection-семантика не подтверждена независимо.

Регрессионный тест `test_factory_multistep_cutoff1_is_visible` проверяет как
структурный decode, так и появление значений в линии редактора.

Поддержка старого 1081-байтового формата остаётся в прежнем opaque reader. Алгоритм выбора параметров по произвольному Selection/Control не выведен; совпадение профиля зависит и от значений. Writer автоматизации и аппаратная логика STORE не изменялись.

Уточнение: профили попадают в `sequence.native_automation`, но не преобразуются в редактируемые дорожки `sequence.automation`; изменение даже одного native значения обычно приводит к `PARTIAL`. Поэтому интеграция не является рабочим декодированием произвольной автоматизации в интерфейсе.

Проверки: новые `tests/test_step_automation_integration.py` проходят; реальные 16 файлов MASTER/drop разобраны без ошибок, 13 профилей распознаны точно, ENV2/MOD/REVERB остались PARTIAL. HARDWARE PASS для автоматизации не заявляется.
